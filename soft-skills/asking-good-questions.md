# Asking good questions

Created 2026-08-03 · Provenance: AI-drafted · Credits: xyproblem.info

## Summary

The XY problem: you're stuck on X, you ask about Y (your attempted workaround),
and everyone burns time on Y while X stays unsolved. Rule of thumb: describe
the *goal*, not the mechanism — "I want X and tried Y, and Y broke this way."

## Lesson

1. Good question = what you're doing + what you expected + what happened +
   what you already tried. The last part is what earns the good answers.
2. Don't ask "is X good?" — ask "for this goal, is X better than Y, and why?"
3. On a team, default to async (well-formed message) over pinging; paste the
   actual error text, not a paraphrase.

## Drill

Self-check: write the question you'd send for your last blocked task. It must
contain all four parts of a good question. If you can't fill in "what I
tried", you haven't debugged enough yet to ask.
